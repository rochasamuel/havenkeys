# Item Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Free-form, reusable tags on every vault item, used to filter the desktop and Android lists and shown, very small, on autofill suggestions.

**Architecture:** Tags live in the sealed `ItemOverview` (`tags: Vec<String>`), normalised by one Rust function (`havenkeys_core::tags::normalize`) on every write. Clients get them with the overviews they already load; tag lists and counts are computed in the UI from those overviews, exactly like the category counts today. The native-messaging `Match` gains `tags` so the extension can label suggestions.

**Tech Stack:** Rust (havenkeys-core, havenkeys-protocol, havenkeys-bridge, havenkeys-mobile/UniFFI), Tauri 2 + React/TS (vitest), MV3 extension TS (vitest), Android Kotlin/Compose (Robolectric tests).

**Spec:** `docs/superpowers/specs/2026-10-07-item-tags-design.md`

### Deviations from the spec (decided while planning; Task 10 updates the spec)

1. `ItemInput.tags` is `Option<Vec<String>>`: `None` **keeps** the stored tags, `Some` replaces them (the `sections` pattern). Many save paths (extension save-login, Android direct saves, imports matching an existing login) do not know about tags; with a plain `Vec` they would erase them.
2. No Rust `list_tags` and no tag filter argument on `list_items`. Desktop and Android already hold every overview in memory (`allItems` / `ItemListUiState.items`); tag counts and the tag filter are computed there, as category counts are.
3. The extension popup has no search box today, so "popup search matches tags" is dropped.

## Global Constraints

- A tag: trimmed, internal whitespace collapsed to one space, lowercased; 1–32 `char`s; no control characters; no comma.
- At most 20 tags per item; stored deduplicated and sorted.
- Tag errors are fixed strings and never echo the input: `"Tag is too long."`, `"Too many tags."`, `"Tag contains a character that is not allowed."`, `"Tag is empty."`.
- Tags are never logged; `Debug` impls stay `finish_non_exhaustive` without tags.
- No server change, no SQLite change, no vault format bump. `PROTOCOL_VERSION` stays 1.
- Extension frame geometry unchanged (`content/frames.ts` rows stay 46px).
- No per-tag colours. A tag pill is the outlined muted pill (desktop `.chip`, Android `PillTone.Outline`).
- Desktop CSP: no inline styles (CSSOM only). Android: no Material; every control ≥ 48dp.
- Commits: conventional style (`feat(core): …`), **no Co-Authored-By trailer**.

## Review Focus

1. **A save path that does not send tags must keep them.** Extension "update password" on a tagged login, Android save of a login, import upgrading an existing login → tags unchanged. (Task 1 test `an_update_without_tags_keeps_them`.)
2. **Restore from an encrypted backup keeps tags.** `restore::rebuild` builds a fresh `ItemInput`; without `tags: Some(..)` restored items lose them. (Task 2 test.)
3. **A long username with tags in the extension menu** must show the username first; tags truncate, never the username. (Task 4 test checks DOM order and classes; CSS `flex-shrink` ratio.)
4. **A Bitwarden folder name with a comma or over 32 chars** must not fail the whole import; it lands in the notes. (Task 2 test.)
5. **Desktop tag filter whose tag vanishes** (last item untagged, deleted, or a sync removes it) falls back to All items instead of an empty list titled with a dead tag. (Task 7 test.)

- [ ] **Step 2: Write `tags.rs` implementation above the tests**

```rust
//! Item tags (spec 2026-10-07-item-tags §3.2): free-form labels the user
//! puts on items to group them. Every write path normalises through here,
//! so "Staging", " staging " and "STAGING" are one tag on every device.

use crate::error::{Error, Result};

pub const MAX_TAGS: usize = 20;
pub const MAX_TAG_CHARS: usize = 32;

/// One tag as stored: trimmed, inner whitespace collapsed, lowercase.
/// Errors are fixed strings; the input is never echoed.
pub fn normalize_one(raw: &str) -> Result<String> {
    let tag = raw.split_whitespace().collect::<Vec<_>>().join(" ").to_lowercase();
    if tag.is_empty() {
        return Err(Error::InvalidInput("Tag is empty."));
    }
    if tag.chars().count() > MAX_TAG_CHARS {
        return Err(Error::InvalidInput("Tag is too long."));
    }
    if tag.chars().any(|c| c.is_control() || c == ',') {
        return Err(Error::InvalidInput("Tag contains a character that is not allowed."));
    }
    Ok(tag)
}

/// An item's whole tag set: each normalised, deduplicated, sorted, at most
/// [`MAX_TAGS`].
pub fn normalize(raw: &[String]) -> Result<Vec<String>> {
    let mut tags = raw.iter().map(|t| normalize_one(t)).collect::<Result<Vec<_>>>()?;
    tags.sort();
    tags.dedup();
    if tags.len() > MAX_TAGS {
        return Err(Error::InvalidInput("Too many tags."));
    }
    Ok(tags)
}
```

Note: `split_whitespace` turns `\n` and `\t` into separators, so `"a\nb"` is stored as `"a b"`; `\u{0}` is not whitespace and is refused. Check `crate::error` exports `Result` (it does: `vault.rs` uses `Result<…>` from it); if the alias is named differently, use the one `vault.rs` imports.

Add `pub mod tags;` to `crates/havenkeys-core/src/lib.rs` in alphabetical order (after `pub mod sync;`).

```rust
/// Imported folder or tag names as HavenKeys tags: the ones that normalise
/// (at most [`crate::tags::MAX_TAGS`], in source order), and the rest as
/// they came, for the caller to keep in the notes rather than drop.
pub(crate) fn split_tags(raw: Vec<String>) -> (Vec<String>, Vec<String>) {
    let mut ok: Vec<String> = Vec::new();
    let mut rejected = Vec::new();
    for value in raw {
        match crate::tags::normalize_one(&value) {
            Ok(tag) if ok.contains(&tag) => {}
            Ok(tag) if ok.len() < crate::tags::MAX_TAGS => ok.push(tag),
            _ => rejected.push(value),
        }
    }
    ok.sort();
    (ok, rejected)
}
```

```ts
import type { ItemOverview } from "./types";

export const MAX_TAGS = 20;
export const MAX_TAG_CHARS = 32;

/** What Rust will store for `raw`, or null if Rust would refuse it. Rust decides; this only guides typing. */
export function cleanTag(raw: string): string | null {
  const tag = raw.trim().split(/\s+/).join(" ").toLowerCase();
  if (!tag || [...tag].length > MAX_TAG_CHARS) return null;
  // eslint-disable-next-line no-control-regex
  if (/[,\u0000-\u001f\u007f-\u009f]/.test(tag)) return null;
  return tag;
}

export interface TagCount {
  name: string;
  count: number;
}

/** Every tag in use with how many items carry it, A–Z. */
export function tagCounts(items: readonly ItemOverview[]): TagCount[] {
  const counts = new Map<string, number>();
  for (const item of items) for (const tag of item.tags) counts.set(tag, (counts.get(tag) ?? 0) + 1);
  return [...counts].map(([name, count]) => ({ name, count })).sort((a, b) => a.name.localeCompare(b.name));
}
```

```tsx
import { useId, useMemo, useState, type KeyboardEvent } from "react";
import { useI18n } from "../i18n";
import { MAX_TAG_CHARS, MAX_TAGS, cleanTag } from "../lib/tags";
import { useVaultTags } from "../lib/vaultTags";
import { Icon } from "./Icon";

interface Props {
  value: string[];
  onChange: (tags: string[]) => void;
  disabled?: boolean;
}

/** One editor row: the item's tags as pills, then a field that suggests the vault's tags. */
export function TagsEditor({ value, onChange, disabled }: Props) {
  const { t } = useI18n();
  const vault = useVaultTags();
  const listId = useId();
  const [text, setText] = useState("");
  const [active, setActive] = useState(0);
  const typed = cleanTag(text);

  const options = useMemo(() => {
    if (!text.trim()) return [];
    const q = text.trim().toLowerCase();
    const found = vault.filter((v) => v.name.includes(q) && !value.includes(v.name)).slice(0, 8);
    const exact = typed !== null && (value.includes(typed) || found.some((f) => f.name === typed));
    return [
      ...found.map((f) => ({ name: f.name, label: f.name, count: f.count as number | null })),
      ...(typed && !exact ? [{ name: typed, label: t.editor.createTag(typed), count: null }] : []),
    ];
  }, [text, typed, vault, value, t]);

  const add = (raw: string) => {
    const tag = cleanTag(raw);
    if (tag && !value.includes(tag) && value.length < MAX_TAGS) onChange([...value, tag].sort());
    setText("");
    setActive(0);
  };

  const onKey = (e: KeyboardEvent<HTMLInputElement>) => {
    if (e.key === "Enter" || e.key === ",") {
      e.preventDefault();
      if (options.length && e.key === "Enter") add(options[Math.min(active, options.length - 1)].name);
      else add(text);
    } else if (e.key === "Backspace" && text === "" && value.length) {
      onChange(value.slice(0, -1));
    } else if (e.key === "ArrowDown") {
      e.preventDefault();
      setActive((a) => Math.min(a + 1, options.length - 1));
    } else if (e.key === "ArrowUp") {
      e.preventDefault();
      setActive((a) => Math.max(a - 1, 0));
    } else if (e.key === "Escape") {
      setText("");
    }
  };

  return (
    <div className="row edit-row tags-edit">
      <span className="row-label">{t.editor.tags}</span>
      <div className="tags-edit-line">
        {value.map((tag) => (
          <span className="chip tag-chip" key={tag}>
            {tag}
            <button type="button" className="tag-remove" disabled={disabled}
              onClick={() => onChange(value.filter((v) => v !== tag))}
              aria-label={t.editor.removeTag(tag)}>
              <Icon name="x" size={12} />
            </button>
          </span>
        ))}
        {value.length >= MAX_TAGS ? (
          <span className="tags-limit">{t.editor.tagLimit}</span>
        ) : (
          <input className="edit-input tags-input" value={text} disabled={disabled}
            maxLength={MAX_TAG_CHARS + 8 /* spaces collapse; Rust has the final say */}
            placeholder={t.editor.addTag} aria-label={t.editor.addTag}
            role="combobox" aria-expanded={options.length > 0} aria-controls={listId}
            aria-activedescendant={options.length ? `${listId}-${active}` : undefined}
```
